# KMP Phase 2: Extract Flavors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `features/chat`, `features/recommendations` and `features/wardrobe` single-variant by moving all GMS code into a new `:platform:gms` module, with no behavior change on either flavor.

**Architecture:** Each GMS-backed capability becomes an interface in its feature's `src/main`, next to a pure-Kotlin no-op stub and a `<feature>NoOpModule` that binds the stubs. Tasks 1–3 do this per feature while the feature's `src/full` still holds the ML Kit implementations. Task 4 moves those implementations into `:platform:gms` (exporting `gmsModule`), removes the feature flavors, and has `app` pick bindings with one `flavorModule` per flavor (`app/src/full`: `gmsModule`; `app/src/foss`: the three no-op modules).

**Tech Stack:** Kotlin 2.4.21, AGP 9.1, Koin 4.2.2 (plain DSL), ML Kit (GenAI Prompt, Image Description, Subject Segmentation, Language ID, Entity Extraction), JUnit 4 + MockK.

**Spec:** `docs/superpowers/specs/2026-11-14-kmp-migration-design.md` — sections "How flavors survive" (including "Chat routing: Phase 2 is a pure refactor") and "Phases" item 2.

## Global Constraints

- Run Gradle from `app-android/`. Git paths are relative to `app-android/`.
- **Pure refactor. No behavior change on either flavor.** Same user-visible strings, same Timber tags and messages, same exceptions and failure messages, same routing order and patterns. The database stays at version 6.
- **Only `app` declares product flavors** after this phase. `features/chat`, `features/recommendations` and `features/wardrobe` lose `flavorDimensions`/`productFlavors` and every `"fullImplementation"(…)` line.
- **GMS dependencies live only in `:platform:gms`** (path `platform/gms`, namespace and package `com.closet.platform.gms`). `app` depends on it with `"fullImplementation"(project(":platform:gms"))`, never `implementation`.
- **Stubs are pure Kotlin in the feature's `src/main`** (no Android-framework or GMS imports beyond what the interface already exposes), so iOS and desktop can bind them later. *Ruling:* the spec's "move `src/foss` stubs to `app/src/foss`" conflicts with its own "iOS and desktop bind the same no-op stubs that foss uses"; stubs go in feature `src/main`, and `app/src/foss` only holds the `flavorModule` that includes them.
- **Reuse existing interfaces.** `CaptionEnrichmentProvider` (core/data) is the image-captioning interface; don't add an `ImageCaptioner`. `NanoInitializer` and `OutfitAiProvider` (core/data) stay as they are. Existing `isSupported` properties and `NanoInitializer` are the capability flags; add no new ones.
- **Koin:** plain DSL (`singleOf`, `single { }`, `bind`/`binds`). Every definition stays a `single`. A class bound to several interfaces is **one** instance.
- **Cancellation:** `CancellationException` is still rethrown everywhere it is today. Move `try/catch` blocks verbatim.
- **Exit criteria for the phase** (spec): `assembleFullDebug` and `assembleFossDebug` succeed; `./gradlew test lint` passes; `:core:data:connectedDebugAndroidTest` passes except the known `MigrationTest` `migrate1To2` and `migrate2To3` cases (removed by the Phase 3 migration consolidation); the foss APK has no GMS classes; a manual smoke test on a device passes for both flavors.

## Review Focus

1. **GMS leaking into foss.** If `:platform:gms` (or any ML Kit artifact) reaches the foss runtime classpath, F-Droid builds break. Expect `apkanalyzer dex packages` on the foss APK to report 0 `com.google.mlkit` / `com.google.android.gms` classes. → Task 4, Step 9.
2. **Non-English chat messages in `full`.** A Spanish question like "¿cuántas prendas tengo?" must still fall through to RAG (`Unrouted`) without touching the DAOs, and the detector must see the original message, not the lowercased one. → Task 1, `PatternChatRouterTest`.
3. **One Nano instance behind three bindings.** `OnDeviceRecommendationProvider`, `OutfitAiProvider` and `NanoInitializer` must resolve to the same object, or the settings "Nano ready" state and the scorer's provider drift apart. → Task 2 (`RecommendationsKoinTest`) and Task 4 (`GmsKoinTest`).
4. **Foss capability flags.** In foss, "Remove background" must stay hidden and captioning must report unsupported, so the UI never offers a GMS-only action. → Task 3, stub tests; Task 4 smoke test.
5. **ML Kit date fallback in `full`.** "what did I wear on April 4" must still resolve (ML Kit, else regex) after the move. This needs the ML Kit model, so it's a smoke-test item. → Task 4, Step 11.
