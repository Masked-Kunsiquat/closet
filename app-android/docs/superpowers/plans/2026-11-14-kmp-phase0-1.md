# KMP Migration — Phase 0 (Toolchain Spike + iOS CI) and Phase 1 (Hilt → Koin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the KMP toolchain works in this build and add an iOS compile check to CI (Phase 0), then replace Hilt with Koin on Android with no behavior change (Phase 1).

**Architecture:** Phase 0 builds a throwaway `:spike:kmp` module on a spike branch to find a working version set. Only the CI workflow, the root `iosCompileCheck` task, and a versions note are merged to `main`. Phase 1 runs on its own branch:
- **Tasks 3–6:** write Koin modules alongside the existing Hilt setup. Each module's graph is checked by a Koin `verify()` unit test, so the build stays green while both DI systems exist.
- **Task 7:** a single cutover switches the entry points and deletes Hilt.

**Tech Stack:** AGP 9.1.0, Kotlin 2.3.20, KSP, Koin (version pinned by Task 1), Room 2.8.4 / Room KMP, Compose Multiplatform (Task 1), GitHub Actions `macos-latest`.

**Spec:** `docs/superpowers/specs/2026-11-14-kmp-migration-design.md`

## Global Constraints

- Run all Gradle commands from `app-android/`. Git paths are relative to `app-android/` (e.g. `git add app/build.gradle.kts`).
- **Android is the only shipped platform.** Nothing in this plan builds an iOS or desktop app.
- **No behavior change in Phase 1.** No schema change. The database stays at **version 6**.
- **Exit criteria for each phase:** `assembleFullDebug` and `assembleFossDebug` succeed, `./gradlew test` passes, `MigrationTest` (`connectedAndroidTest`, `core/data`) passes, the foss APK has no GMS classes, and a manual smoke test on a device or emulator passes.
  - **Baseline exceptions** (found failing on `main` before any change; they are not regressions):
    - `StatsViewModelTest` and `ClothingFormViewModelTest` don't compile against the current code. Repair them first, as test-only commits at the start of Phase 1, before the first `./gradlew test` gate.
    - 2 `SegmentedBarTest` failures, the `MigrationTest` 1→2 and 2→3 cases, and 4 `StatsDaoTest` failures are pre-existing. They're allowed to keep failing; a gate fails only on a *new* failure. They're tracked for a later fix, and the `MigrationTest` cases go away with the Phase 3 migration consolidation.
- **Scope parity:**
  - Every class that is `@Singleton` today, or provided `@Singleton` in a Hilt module, becomes a Koin `single`.
  - Every unscoped `@Inject constructor` class becomes a Koin `factory`.
  - ViewModels become `viewModel`.
- **`AiPreferencesRepository`** is constructed only in `dataModule`'s provider (a `single { … }` body). Never use `singleOf(::AiPreferencesRepository)`.
- **Flavor classes** have different constructors in `src/full` and `src/foss`, so their Koin definitions live in a flavor-specific module (a file in `src/full` and a file in `src/foss` with the same name and `val`), never in `src/main`.
- **Cancellation:** `CancellationException` must still be rethrown at every `getOrElse` / `Result` unwrap. Don't touch error handling in Phase 1.
- **Koin style:** plain Koin DSL (`singleOf`, `factoryOf`, `viewModelOf`, `workerOf`, `bind`), not koin-annotations.

## Review Focus

1. **A former `@Singleton` that becomes `factory`.** For example, a second `EmbeddingIndex` would leave chat retrieval silently empty, because `ClosetApp` loads one instance and chat reads another. Expected: each listed singleton resolves to the same instance twice. Pinned by `SingletonParityTest` (Task 3, Task 5).
2. **`NanoProvider` bound to two interfaces.** `OutfitAiProvider` and `NanoInitializer` must be the same object, or model warm-up initializes an instance nobody uses. Pinned in `RecommendationsKoinTest` (Task 5).
3. **The foss build resolving a full-only class.** A missing or misnamed flavor module crashes on first use of chat or recommendations, not at start-up. Expected: both flavors' graphs verify. Pinned by `AppKoinGraphTest` running under `testFullDebugUnitTest` and `testFossDebugUnitTest` (Task 6).
4. **The outfit builder's shared ViewModel scoped to the wrong back-stack entry.** `OutfitsNavigation` uses `hiltViewModel(parentEntry)`. If the replacement isn't scoped to `parentEntry`, the wardrobe picker edits a different builder and the picked items vanish. Expected: picking items returns them to the builder. Manual smoke step in Task 7, plus a grep check that `koinViewModel(viewModelStoreOwner = it)` is used there.
5. **Workers constructed by the default factory.** If `KoinWorkerFactory` isn't installed, `EmbeddingWorker`, `ImageCompressionWorker` and `BatchSegmentationWorker` crash with `NoSuchMethodException`, and embeddings never build. Expected: after adding an item, its embedding row appears. Pinned by worker definitions in the `verify()` tests (Tasks 3 and 5), plus a manual smoke step in Task 7.
