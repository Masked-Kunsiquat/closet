# Color v2 PR 2: engine and chat read measured color. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the recommendation engine scores colour harmony on measured shades, using OKLCh hue warped onto the painter's wheel, neutrals from `wears_as_neutral`, and share weighting, plus two features that start with no effect and are learned. Chat colour search understands basic terms and returns shares. Base hexes become clothing-realistic.

**Architecture:**
- A data-only `MIGRATION_3_4` re-picks the base hexes.
- The engine gets the measured hex, share and `wears_as_neutral` per tag through the existing `getItemColorHexes` query.
- A new pure `ColorHarmony` object in the engine package owns harmony for both the engine score and the feature extractor, replacing two duplicated implementations.
- Chat resolves basic terms in `LookupResolver` and reads shares through one batched DAO query.

**Tech stack:**
- Kotlin Multiplatform, using `features/recommendations` commonMain and `core/data` commonMain;
- Room KMP with `MigrationTestHelper`;
- kotlin.test.

**Spec:** `docs/superpowers/specs/2026-11-20-color-v2-pr2-design.md` (decisions D1–D7), with the parent spec `docs/superpowers/specs/2026-11-19-color-v2-design.md`.

## Global Constraints
- Run commands from `app-android/`. Git paths are relative to `app-android/`.
- **Purity:** commonMain stays pure (no `android.*`, `java.*` or WorkManager). The engine stays pure, with no I/O and no clock.
- **Errors:** repositories return `DataResult`. Rethrow `CancellationException` at every unwrap.
- **Migrations** follow `core/data/src/commonMain/kotlin/com/closet/core/data/migrations/AGENTS.md`:
  - drop `one_ootd_per_day` first;
  - use frozen literal SQL, and never call `DatabaseSeeder`;
  - never edit an applied migration (`MIGRATION_1_2`, `MIGRATION_2_3`).
- **Colour constants:**
  - `C_FLOOR = 0.03` (OKLCh chroma);
  - analogous gap ≤ 60°, complementary folded gap ≥ 150°, both × 1.05; everything else × 1.0, with no clash band;
  - warp anchors (OKLCh hue → wheel position): 29→0, 71→60, 110→120, 143→180, 266→240, 328→300, piecewise-linear and wrapping at 360.
- **Hex parsing:** use `com.closet.core.data.color.Oklab` (`fromHex`, `chroma`, `hueDegrees`; `Lab.l`). Don't write a second converter. `Oklab.fromHex` throws on anything except `#RRGGBB`, so every engine call site must handle malformed input (see Review Focus).
- **Weights:** `TASTE_WEIGHTS_SCHEMA_VERSION` = `"v3"` and `FEATURE_COUNT` = 10.
- **Chat:** the tool description stays ≤ 180 characters (`ToolSpecTest`), and item lists keep their cap of 20.
- **Gradle:** memory is tight, so run one invocation at a time in the foreground, never with `--rerun-tasks`, and never kill the daemons.
- **Commits** are signed. Never bypass signing; on a signing error, stop and report BLOCKED. Never stage `.claude/settings.json`.

## Review Focus
1. **A malformed or lowercase hex in `clothing_item_colors.hex` or `colors.hex`** must not crash scoring. A measured hex that won't parse falls back to the name hex, and when neither parses the tag is skipped. Test: in Task 2, `a malformed measured hex falls back to the name hex`.
2. **An item with no colour tags, or only neutral ones,** sits out of harmony. An outfit with fewer than two harmony colours scores × 1.0. Test: Task 2, `an all-neutral outfit has no colour effect`.
3. **A corrupt share** (negative, above 1, or NaN) is clamped to [0, 1], and NaN is treated as missing. Missing shares on any tag mean that every tag on the item gets `1 / n`. Test: Task 2, `shares are clamped and missing shares split evenly`.
4. **Red hues across the 0/360 wrap** (Burgundy 13°, Pink 4°, re-picked Red 20°) warp into 300–360 and fold correctly against greens. Test: Task 2, `warp is continuous across the wrap`.
5. **Chat value casing and spelling:** "BLUE", "Grey" and "gray" resolve the same way as their lower-case forms, and an unknown value's `valid_values` lists the basic terms too. Test: Task 4, `basic terms resolve case-insensitively and grey means gray`.

**Interfaces:**

- Produces:
  - `data class ColorHex(val hex: String, val family: String, val share: Double? = null, val wearsAsNeutral: Boolean = false)`. `hex` is the measured hex, or the name hex when there is no measurement. The VM maps `ColorHex(it.measuredHex ?: it.hex, it.colorFamily, it.share, it.wearsAsNeutral)`, keeping `it.hex` as the fallback when `measuredHex` fails to parse, by passing a second field or resolving the hex in the VM (implementer's choice, so long as Review Focus 1 holds).
  - `internal object ColorWheel { fun warp(oklchHue: Double): Double; fun gap(a: Double, b: Double): Double }`. `warp` returns a value in [0, 360); `gap` returns the folded angular distance in [0, 180].
  - `internal data class HarmonyColor(val wheelHue: Double, val chroma: Double, val lightness: Double, val family: String, val share: Double)`
  - `internal object ColorHarmony`:
    - `C_FLOOR = 0.03`
    - `fun harmonyColor(item: EngineItem): HarmonyColor?`: the largest-share non-neutral tag, with ties going to the earlier tag in list order; null when none.
    - `fun hueMultiplier(gap: Double): Double`
    - `fun familyRule(a: String, b: String): Double`: moved verbatim from `OutfitFeatureExtractor.pairHarmonyMultiplier`.
    - `fun factors(items: List<EngineItem>): ColorHarmonyFactors`
  - `PairScorer.hueTerm(a, b): Double?` = `hueMultiplier(gap)` of the two harmony colours, or null when either is null. It is unweighted; the share weighting lives in `factors`.

**How `factors` works (D3 and D4):**
1. Collect `harmonyColor` for each item, keeping only non-null ones. With fewer than 2, return `(1.0, 1.0)`.
2. For each pair: `hue = hueMultiplier(gap)`, `fam = familyRule(fA, fB)`, and `w = sA * sB`.
3. If `fA != fB || hue >= fam`, add `w * ln(hue)` to `hueLog`; otherwise add `w * ln(fam)` to `famLog`.
4. Return `ColorHarmonyFactors(exp(hueLog / n), exp(famLog / n))`, where `n` is the pair count.

The engine's `colorHarmonyMultiplier(items)` returns `ColorHarmony.factors(items).combined`.

**A tag is neutral** when `wearsAsNeutral`, or when the chroma of its parsed hex is below `C_FLOOR`.

**The tag's share:** clamp it to [0, 1], with NaN treated as null. If any of the item's tags has a null share, every tag gets `1 / tags.size`.
